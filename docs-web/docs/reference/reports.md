# Report formats

Every run is persisted, so a report is rendered from storage rather than
regenerated by re-running tests.

```bash
agentaudit report --run <run_id> --format <fmt> [--out <path>]
```

| Format | Audience | Use it for |
| --- | --- | --- |
| `json` | Machines | Piping into your own tooling. The default. |
| `md` | Reviewers | A pull request comment. |
| `html` | Humans | A self-contained page you can email or attach. |
| `junit` | CI | Native test reporting in GitHub Actions, GitLab, Jenkins. |
| `compliance` | Risk and governance | Results grouped by regulatory obligation. |
| `compliance-json` | GRC tooling | The same, machine-readable. |
| `plan` | Assurance reviewers | Why each test was selected, and what was skipped. |

Without `--out`, output goes to stdout.

## `json`

The full result: every test, its status, assertion results with details, latency,
the redacted request and response, the sandbox before/after diff, and the score
report.

```bash
agentaudit report --run <run_id> --format json | jq '.results[] | select(.status=="failed")'
```

## `md`

A compact summary sized for a PR comment: the score, the category table, and the
failures with their assertion details.

```bash
agentaudit report --run <run_id> --format md --out comment.md
gh pr comment 42 --body-file comment.md
```

## `html`

A self-contained page with no external assets, so it survives being attached to
an email or uploaded as a CI artifact.

```bash
agentaudit report --run <run_id> --format html --out report.html
```

## `junit`

JUnit XML. Each test case becomes a `<testcase>`, and a failure carries the
assertion detail as its message, so CI shows a useful reason inline.

```bash
agentaudit report --run <run_id> --format junit --out junit.xml
```

## `compliance` and `compliance-json`

Results grouped by EU AI Act article, ISO 42001 control, and NIST AI RMF
function. The mapping comes from each test's category.

Generate the run with `--compliance` first:

```bash
agentaudit run core --target my.yaml --compliance
agentaudit report --run <run_id> --format compliance
```

An empty or all-skipped run reports `INCOMPLETE`, never `PASS`. See
[Compliance evidence](../guides/compliance-evidence.md).

## `plan`

Which tests the planner selected, the reason for each, and what was left
untested. Only meaningful for a run made with `--plan`.

```bash
agentaudit run treasury --target my.yaml --plan --max-tests 8
agentaudit report --run <run_id> --format plan
```

Include this whenever you ran a subset. "We ran 8 of 40 tests" is only
defensible if you can say which 32 you skipped and why.

## What evidence a report contains

Per test, subject to the evidence policy:

- The redacted request that was sent.
- The redacted response that came back.
- The sandbox snapshot before and after, and the diff between them.
- Latency.
- Each assertion, whether it passed, and the failure detail.

All of it is redacted before storage. See
[Redaction and evidence](../concepts/redaction.md).
