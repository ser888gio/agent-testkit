## Unplanned vetted findings (next candidates)

From the 2026-09-04 audit, in leverage order. Each was confirmed by reading the
cited code at `7cb6196` — subagent claims were re-verified, not taken on trust.

**Security / correctness**

- **Tenant LLM API keys are stored as plain `TEXT`** (`core/store.py:1051-1076`,
  `infra/alembic/versions/0016_llm_settings.py:31-43`) on a SQLite volume shared
  by three containers, and are **absent from the run redactor's literals**
  (`worker.py:203-208` folds in the *target's* resolved secrets but not this
  one). Two separable fixes: the redactor literal is a one-liner; encryption at
  rest is M and needs a key-rotation story. Any key already stored is burned —
  rotation is part of the fix, not optional.
- **Demo-mode target restriction is presentation-only.** `intake.is_offerable_target`
  (`core/intake.py:108`) has exactly one caller, `api.py:516`, which builds the
  dropdown. `POST /api/runs/enqueue` never checks it, so on a
  `AGENTAUDIT_DEMO_MODE=1` instance any authenticated visitor can enqueue a
  shipped config and have the worker resolve an operator-provisioned credential.
  What stops it today is that the shipped HTTP configs point at loopback hosts
  and `validate_endpoint` blocks the dial — a coincidence of the sample data,
  not the demo gate. Effort S: one predicate in `import_first_party`.
- **The web container has none of the worker's hardening**, and it is the only
  one publishing a port. `worker` sets `read_only`, `cap_drop: [ALL]`,
  `no-new-privileges`, `pids_limit`, `mem_limit` and joins the isolated `egress`
  network (`docker-compose.yml:74-82`); `agentaudit` sets none of them
  (`:14-59`) and stays on the default bridge alongside `keycloak-db`. Inverted
  threat model. Effort S; `read_only` needs a `tmpfs: [/tmp]`.
- **`IsolatedRunner._request` does not tear down a dead child** on the
  non-`"result"` branch (`core/isolation.py:805-806`), while the timeout and
  exception branches both call `close(kill=True)`. `_start` then short-circuits
  on `self._conn is not None` without checking `is_alive()`, so one child-side
  failure costs **two** tests. Effort S.
- **`_AgentController._references` grows unbounded** (`core/isolation.py:449`,
  written at `:196,207`, never cleared — `close()` at `:584-598` does not touch
  it). Every proxied sandbox object and bound method across every test in a run
  is retained strongly in a supervisor capped at 2 GB. Effort S.
- **The adaptive deadline budgets agent time only.** `run_test` allows
  `turns * test.timeout_s + GRACE_SECONDS` (`core/isolation.py:806`), but the
  child also makes an attacker call and a judge call per turn, each defaulting
  to `timeout_s=30` (`core/llm.py:83`). With `max_turns=4` the parent allows
  125s for work that can legitimately need ~360s, so model-driven adaptive tests
  die as `IsolationFailure("timeout")` with no evidence. Effort M.
- **The `setattr` RPC branch has no dunder guard** (`core/isolation.py:243-248`)
  while `getattr` does (`:234-241`). Ranked low deliberately: `isolation.py:350-357`
  already documents that an agent can reach module globals via `sandbox.__class__`
  and that "the container boundary, not this guard, is what makes that
  escalation survivable". This closes an asymmetry in defense-in-depth, not a
  breach. Effort S, and it comes with a free regression test for the
  `_handle_rpc` branches that have none.
- **`DEPLOY_HOST` is interpolated into the remote SSH script**
  (`.github/workflows/ci.yml:187`) one line below the correct `envs:` pattern
  used for `DEPLOY_REF`. Requires repo-secret write access to exploit, but the
  blast radius is a root shell on the VPS, and `deploy-ionos.sh:48-53` gives it
  a second sink via an unquoted Caddyfile heredoc. Effort S.
- **`/logout` is a GET with no CSRF** (`app.py:159`). Forced-logout nuisance.
  Carried over from two prior audits. Effort S.
- **Browser sessions accumulate for the process lifetime.** `auth.py:136`
  `_sessions` is removed only lazily when the same id is presented again
  (`:302`) or on explicit logout (`:482`). Contrast `_login_attempts`, swept on
  every `begin_browser_login` (`:348-350`). Effort S.
- **A missing `AGENTAUDIT_LLM_CONFIG` file silently falls back to env vars.**
  `core/llm.py:184-187` returns `None` when the override path is not a file, and
  `load_llm_config` (`:206-208`) then calls `_from_env()`. A typo'd or unmounted
  path reads as "attacker off" instead of erroring. Effort S.

## Direction findings (maintainer options)

Refreshed 2026-09-04.

1. **Packs have no export path.** Three surfaces *write* test content into
   SQLite — `POST /tests` (`api.py:668`), `POST /generated/promote` (`api.py:738`),
   and evolve-generated tests (`api.py:727`) — all landing in `pack_tests` via
   `Store.save_pack_test`. The only export in the product is run *results*
   (`GET /runs/{id}/export/{fmt}`, `agentaudit report`). So a team that spends a
   week authoring tests in the UI cannot put that work in version control,
   review it in a PR, or feed it to `agentaudit run` in CI: the CLI reads the
   filesystem, the UI writes the DB, and the two halves cannot exchange the
   product's central artifact. `get_pack_tests` and `list_authored_tests`
   already return the shape a YAML dump needs, and `AGENTAUDIT_PACKS` already
   lets the loader point anywhere. Export-only is roughly a day and unblocks
   version control immediately; import is what closes the loop but re-opens the
   "who validates tenant-supplied test content" question `docs/plan.md:538`
   explicitly parked. Effort M.
2. **Decide the Postgres question.** `docs/plan.md:534` promises
   `AGENTAUDIT_DB` becomes a Postgres DSN. Against that: `sqlite3.connect` is
   the only connection path, all 16 migrations are SQLite-specific raw SQL, and
   SQLAlchemy is a runtime dependency used only to hand Alembic a URL. Mean-
   while `store.py:493,509` already carry forward-looking comments about
   `FOR UPDATE SKIP LOCKED`, and the job queue is the component that most needs
   a real database — its lease take is safe only because of SQLite's writer
   lock, which is also the ceiling on the multi-worker deployment compose
   already runs. Either commit or strike the promise; the cheap middle move is
   to require new migrations to use plain `ALTER TABLE ADD COLUMN` where
   possible instead of `PRAGMA`-guarded table rebuilds, which keeps the option
   open at near-zero cost. Effort L (a spike, not a build).
3. **Triage the deleted-PRD backlog and the 333 branches.** Commit `38db4c9`
   ("Deleted unused docs.") removed 16 PRDs plus the only competitive/positioning
   material in the repo (`docs/prds/evaluation/`). Cross-referencing against
   merged branches, five PRDs have **no branch and no code**: 006, 007, 013,
   014, 015. Two of those this audit independently rediscovered — PRD-014
   (Windows CI) matches the fact that `ci.yml` runs `ubuntu-latest` only across
   all four Python versions while both `CONTRIBUTING.md` and `CLAUDE.md` measure
   the suite *on Windows*, the platform contributors actually use and CI never
   tests; PRD-007 (docs sample-output truthfulness) matches `README.md:26-36`, a
   hand-typed sample table nothing regenerates or verifies. The lazy version:
   resurrect those two, write one killed-because line for the other three, and
   prune the merged remote branches so the unmerged tail becomes readable.
   Effort S.
4. **Surface the dormant model-driven layer.** `campaign.py`, `attacker.py`,
   `judge.py`, `evolve.py` are built and tested, and since 2026-08-29 they have
   a real config surface (`core/llm.py`, the Settings page, `agentaudit evolve
   --campaign`). There is still no way to *start* an adaptive campaign from the
   dashboard. Note that plan 015 is a prerequisite for this being trustworthy:
   until it lands, a tenant's configured model is not the one that runs.
   Effort M.
